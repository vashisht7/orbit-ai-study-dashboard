Bridge the remaining gaps · five short study notes

1. Classical ML and a simple baseline

Before choosing an LLM, identify the prediction target and build a simple baseline. Linear regression predicts a number; logistic regression predicts a binary probability; trees split features into regions. Compare on the same held-out data. For a document-routing task, try TF–IDF plus a linear classifier before a costly fine-tune. K-means groups similar points without target labels; cluster IDs are not automatically meaningful categories.

Try Code Lab’s gradient step, TF–IDF, and k-means update. Next depth: regularization, tree ensembles, cross-validation, and feature preprocessing.

2. Calibration and controlled experiments

A model that says 0.8 confidence should be correct about 80% of the time among comparable predictions at that confidence. Softmax alone does not establish this. Group predictions into probability bins and compare average confidence with observed accuracy. An A/B test instead compares user outcomes after random assignment; decide the success metric and stopping rule before examining results. Correlation in logs does not prove the new model caused an improvement.

Exercise: explain how a model can rank examples well but have misleading probabilities. Extend classification metrics with threshold sweeps and confidence bins.

3. SQL and data-pipeline correctness

State the meaning of one row before joining data. A one-to-many join can multiply rows and inflate counts. Window functions retain rows while calculating ranks or running totals. For streaming data, event time is when something happened; processing time is when you saw it. Late records require an explicit correction policy. Use stable event IDs to deduplicate retries and reconcile source totals after transformations.

Try dense ranking and deduplication. Follow with real SQL joins, EXPLAIN plans, Spark partitioning, and a late-event exercise.

4. Distributed training and recovery

Data parallelism gives each worker different examples and synchronizes gradients. Model parallelism splits the model across devices when it is too large for one device. Communication can erase expected speedups, so measure it. A resumable checkpoint may need weights, optimizer state, random-generator state, and data position. Saving only weights is useful for inference but does not reproduce the next training step.

Try resumable iteration. Next depth: gradient synchronization, sharding, mixed precision, and checkpoint recovery using actual multi-device tools.

5. Retrieval and multimodal evaluation depth

Use exact nearest-neighbor search as a baseline before adopting an approximate index. Measure how often approximate search preserves useful candidates under a latency budget. For images and speech, preserve the original asset and the transformation history; a transcript or caption can omit critical evidence. Recommendation and computer-vision roles additionally need their own datasets, modeling choices, and metrics.

Compare exact retrieval with recall@k and NDCG. A toy implementation establishes mechanics, not production readiness.

Further study: Google’s ML curriculum · PyTorch fundamentals. Review date: October 4, 2026.
